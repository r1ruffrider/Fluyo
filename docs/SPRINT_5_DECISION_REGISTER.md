## Current web routes and acquisition gaps

The application currently provides public `/`, `/learn`, `/login`, `/forgot-password`, and `/pricing` routes; session-dependent callback/reset routes; and protected `/account`, `/billing`, and `/dashboard` routes. The public `/learn` experience is a browser-local three-choice preview; the authenticated dashboard uses server-owned learning contracts.

There is no durable early-access/waitlist submission, marketing-consent record, unsubscribe endpoint, creator-application endpoint, campaign resolver/deep-link attribution endpoint, public mobile-tester enrollment, store redirect, or social publishing/webhook integration. Those absences are explicit blockers, not implied future contracts.
